## 一、选题的目的及意义

**1. 背景：**

水果是高频刚需消费品，线上购买的规模逐年增长，但生鲜品类的线上经营与其他商品有明显差别。水果品种多、规格杂、保质期短、损耗高，用户又存在显著的口味差异和季节偏好。商家如果用统一的热销榜单或简单的分类列表展示商品，用户很难在较短时间内找到既合口味又当季新鲜的商品，浏览成本高、放弃率高；同时热销品容易缺货、滞销品容易积压腐烂，库存周转压力大，进货决策也缺少数据支撑。因此，把推荐能力与水果商城的商品、库存、订单等核心对象结合起来，形成可解释、可干预的个性化展示，是这类系统需要解决的实际问题。

**2. 目的：**

本课题旨在设计并实现一套面向单商家自营的水果商城系统，完成商品建档、浏览选购、购物车、订单确认、模拟支付、履约交付到售后评价的完整业务闭环，支持消费者（会员）、商家运营人员与履约售后人员协同工作。在此基础上实现多因素推荐这一核心智能化功能：依据业务对象属性、用户需求、历史行为与时空条件构造特征，对候选商品排序并展示主要推荐依据，同时允许人工调整推荐策略，使系统既满足个性化选购需求，也能服务于库存周转与经营决策。工程上系统须具备身份认证、角色权限、数据校验、组合条件与分页查询、统计可视化、操作日志与异常处理能力，并对商品上下架、库存扣减、订单取消、模拟支付、履约与售后的状态一致性进行校验，数据库结构须反映核心对象之间的真实关系。

**3. 意义：**

本课题将推荐方法应用于生鲜水果这一垂直电商场景，考察基于内容的多因素加权与简单协同过滤在非标、易腐、强时令品类上的表现，为同类场景的特征构造与排序权重设计提供实践参考；系统中批次库存管理、状态机校验、并发扣减与权限控制的实现过程，也是对软件工程与数据库设计方法的综合应用。对消费者而言，个性化推荐能缩短挑选时间、帮助发现当季新品；对商家而言，推荐与库存协同有助于带动长尾商品销售、减少损耗，经营分析可为进货与营销提供数据支撑；从社会效益看，减少因滞销造成的食物浪费符合绿色低碳的发展方向，规范化的商品与库存记录也有利于食品安全追溯。

## 二、设计的主要内容

> **原模板要求**：
> 1. 软件系统类，写出系统核心功能，并有文字阐述，200字以上；

### 1. 软件系统类（模板要求 ≥200 字，本稿约 700 字）

**【填写内容】**

本系统面向消费者与商家，围绕水果商城的核心对象和业务流程开展服务，使用者为消费者（会员）、商家运营人员与履约售后人员三类，业务围绕商品、特色属性、库存、购物车、订单、模拟支付和履约记录展开，形成"商品建档→浏览选购→购物车→订单确认→模拟支付→履约交付→售后评价"的完整业务闭环。系统功能包括六个方面。一是供应与库存协同：商家按 SPU/SKU 两级为水果建档，维护品种、产地、规格、甜度、口感、储存条件、保质期与应季月份等特色属性；库存按入库批次记录到货日期、剩余数量与成本，并用库存流水记录预占、扣减、释放、报损和盘点调整，扣减时按先进先出选择批次，对临期与低库存批次给出预警，使供应信息与可售库存保持一致。二是分类检索与个性化展示：支持多级分类浏览、关键词检索、按产地与价格筛选、排序与分页，并在首页与详情页展示带推荐依据的个性化商品位。三是购物车与订单管理：支持加购、改量、选中结算、失效商品提示与金额小计；下单时重新校验价格与库存并生成商品快照，支持订单确认、查询、取消与状态跟踪。四是模拟支付与履约跟踪：通过模拟支付网关完成待支付、支付中、成功、失败、关闭与退款的状态流转；支付成功后生成履约单，按分拣、打包、配送、送达、签收推进，并保留可追溯的履约时间轴。五是售后评价与经营分析：支持售后申请与审核、退款处理和订单评价，并向商家输出销售趋势、品类占比、库存周转与滞销商品等统计可视化结果。六是工程支撑能力：实现身份认证与基于角色的权限控制、数据校验、组合条件分页查询、操作日志留痕与统一异常处理。系统对商品上下架、库存扣减、订单取消、模拟支付、履约推进与售后处理实施状态一致性校验，数据库表结构按核心对象的真实关系设计，保证业务数据可核对、可追溯。

### 2. 算法类（模板要求 ≥200 字，本稿约 640 字）

**【填写内容】**

本课题以水果商城的商品推荐作为核心智能化功能，实现一种面向生鲜品类的多因素推荐模型。算法依据业务对象属性、用户需求、历史行为与时空条件构造特征：商品侧取分类、产地、规格、甜度与酸度、脆度口感、单价、糖度、品级、应季月份和保质期等属性并作归一化；用户侧取口味偏好、忌口与可接受价格区间等显式需求，以及由浏览、搜索、收藏、加购、下单和评价等行为按行为权重聚合并施加时间衰减得到的隐式偏好；情境侧取当前季节、时段与配送区域。候选商品由内容相似、时令匹配、热销商品和库存协同等通道召回后合并去重，再按上述多因素加权求和计算得分并排序：当某个特征缺失时该维度不计入权重分母，其余权重重新归一化，避免把缺失值当作零分而误伤新用户与新品；同时对重复购买周期、忌口冲突和负反馈设置惩罚项，排序后采用多样性策略打散，避免结果集中于单一品类。本次实现选用基于内容的匹配多因素加权作为主要排序方案，并以简单协同过滤（物品共现）作为召回补充与对比基线。系统为每条推荐结果展示主要推荐依据，如"当季上市""口味匹配""同类复购""近期热销"，并允许商家在后台调整各因素权重、置顶与屏蔽规则，允许用户修改偏好或标记"不感兴趣"，使推荐结果可解释、可干预。算法效果采用典型样例验证：以模拟数据与公开生鲜购物篮数据构造实验，按时间切分训练集与测试集，考察相关性（准确率、NDCG）、商品覆盖率与长尾商品曝光占比，与随机推荐、热销榜单和纯协同过滤方案对比，并针对新用户、新商品、候选商品不足、忌口冲突、库存为零与推荐计算异常等边界条件逐条验证。

### 1. 技术要求（模板要求 ≥150 字，本稿约 420 字）

**【填写内容】**

系统采用前后端分离的 B/S 架构。后端使用 Java 17 与 Spring Boot 3 搭建分层工程，按 Controller、Service、Mapper 三层组织代码；身份认证采用 JWT 实现无状态登录，授权基于 RBAC 模型控制用户、角色与菜单权限，通过拦截器配合自定义权限注解完成接口级鉴权，用户密码使用 BCrypt 加密存储。持久层使用 MyBatis-Plus 操作 MySQL 8：分页查询由分页插件完成，支持组合条件筛选；库存扣减使用条件更新语句并通过判断影响行数确定成败，配合事务保证并发下单不出现超卖与负库存。缓存使用 Redis 存放热点商品数据与推荐结果。推荐模块以 Java 实现，包含特征构建、多通道召回、加权排序、推荐理由生成与离线评估。前端消费者端使用 Vue 3 与 Vant 构建移动端 H5 页面，商家端使用 Vue 3 与 Element Plus 构建，统计图表使用 ECharts 绘制。接口遵循统一的响应体与错误码规范，接口文档由 Knife4j 自动生成；操作日志通过自定义注解与切面自动落库；异常统一处理，并按参数校验、权限、业务与系统异常分类返回。开发使用 Maven 管理依赖、Git 管理版本，测试使用 JUnit 5 完成单元测试、Apifox 完成接口测试、JMeter 完成并发测试。
