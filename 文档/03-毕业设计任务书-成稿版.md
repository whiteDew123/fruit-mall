## 一、选题的目的及意义

> **说明**：此栏由老师撰写，原 `.doc` 中已完成。以下**原文照录**备查，**不要改动、不要重写**；Word 里保持原样即可。

**1. 背景：**

随着移动互联网普及，生鲜水果作为高频刚需产品，线上交易市场爆发式增长。传统线下销售受限于地理位置、营业时间和库存周转，难以满足现代消费者对便捷性、多样性和个性化的需求。当前生鲜电商平台虽多，但痛点明显：面对海量水果品种，用户往往难以快速找到符合口味偏好或当前需求的产品，浏览时间过长易导致放弃购买；多数平台采用简单分类列表或热门排行展示商品，忽视用户个体差异（如历史购买记录、口味偏好、季节性需求），"千人一面"现象严重，转化率较低；水果易腐坏，对库存周转要求极高，缺乏精准需求预测和智能推荐，易导致热销品缺货、滞销品积压腐烂，增加运营成本。因此，设计并实现一个具备基础交易功能且能通过智能算法解决上述痛点的"基于推荐算法的水果商城"，是当前生鲜电商领域亟待解决的问题。

**2. 目的：**

本课题旨在设计并开发一套功能完善、具备智能化推荐能力的水果商城系统。具体目标是实现从商品建档、浏览选购、购物车管理、订单确认、模拟支付到履约售后的全链路闭环，支持消费者、商家运营人员及售后人员多角色协同，保证数据真实性和一致性。系统的核心智能化功能在于推荐算法的实现与优化，将根据业务对象属性、用户历史行为或时空条件构造特征，采用基于内容的匹配多因素加权或协同过滤算法，实现"千人千面"个性化商品展示，并能展示推荐理由、允许人工调整，以验证算法的有效性。在工程实现上，将包含身份认证、角色权限控制、数据校验、分页查询及统计可视化操作，注重日志记录和异常处理，确保系统稳定性。同时遵循最小必要原则授权，不收集与业务无关的个人信息，演示采用模拟或脱敏数据，确保用户隐私安全。预期成果是一套可运行的软件系统，能完成常规水果买卖操作，并通过智能推荐显著提升用户体验和商家销售效率。

**3. 意义：**

本课题将推荐系统理论应用于水果销售这一垂直电商领域，探索基于内容的匹配或协同过滤算法在生鲜非标品场景的应用效果，丰富推荐算法在特定场景下的特征工程构建方法，为后续研究提供实证参考。同时，系统设计中涉及的数据库一致性校验、权限控制模型等，也是对软件工程理论的综合性应用。在实践层面，对消费者而言，智能推荐大幅缩短搜索时间，帮助发现潜在感兴趣的新鲜水果，提升购物乐趣和满意度；对商家而言，精准推荐能有效带动长尾商品销售，减少库存积压损耗，提高客单价和复购率，经营分析功能还能为进货决策和营销活动提供数据支持；对开发者而言，这是从需求分析、算法设计到系统落地的全流程工程实践，极大提升综合技术能力。在社会效益方面，系统推广有助于推动传统水果零售行业数字化转型，促进农业供应链优化升级，提高流通效率、减少因滞销导致的食物浪费，符合绿色可持续发展理念。规范化电商平台建设也有助于保障食品安全追溯，提升社会整体生活质量。

## 二、设计的主要内容

> **原模板要求**：
> 1. 软件系统类，写出系统核心功能，并有文字阐述，200字以上；
> 2. 算法类，提出系统模型、设计算法、实验验证及仿真效果，200字以上。

### 1. 软件系统类（模板要求 ≥200 字，本稿约 500 字）

**【填写内容】**

本系统面向消费者、商家运营人员与履约售后人员三类使用者，围绕水果商城的核心业务对象和业务流程开展服务，形成"商品建档→浏览选购→购物车→订单确认→模拟支付→履约交付→售后评价"的完整业务闭环，采用前后端分离的 B/S 架构自行搭建分层工程骨架。系统核心功能包括八个部分：一是身份认证与角色权限管理，采用 JSON Web Token 实现无状态登录，基于 RBAC 模型控制用户、角色与菜单权限，并在服务层校验数据归属，对手机号、收货地址等个人信息遵循最小必要原则脱敏展示；二是商品与特色属性建档，按 SPU/SKU 两级结构维护水果的品种、产地、规格、甜度、口感、储存条件、保质期与应季月份等特色属性；三是分类检索与个性化展示，支持多级分类浏览、关键词检索、按产地与价格筛选，并在首页与商品详情页展示带推荐依据的个性化推荐；四是库存协同管理，按入库批次记录到货日期、保质期与剩余数量，提供库存流水、临期预警与低库存提醒，支持按批次先进先出扣减；五是购物车与订单管理，支持商品加购、数量修改、失效商品提示、订单确认与订单取消；六是模拟支付与履约跟踪，通过模拟支付网关完成支付状态流转，履约记录支持分拣、打包、配送、签收的全过程时间轴追踪；七是售后评价与经营分析，支持售后申请与审核、订单评价，并输出销售趋势、品类占比、库存周转与滞销商品分析；八是操作日志与异常处理，对关键操作进行留痕记录并提供统一的异常响应与降级处理。系统数据校验覆盖商品上下架、库存扣减、订单取消、模拟支付、履约推进与售后状态一致性。

### 2. 算法类（模板要求 ≥200 字，本稿约 480 字）

**【填写内容】**

本课题以水果商城多因素推荐作为系统的核心智能化功能，提出并实现一种面向生鲜品类的多因素加权推荐模型。系统采用"召回—过滤—排序"两阶段推荐框架：召回阶段通过内容相似、时令匹配、热销榜单、物品协同过滤与库存协同五个通道生成候选商品集合，兼顾推荐多样性并缓解新用户冷启动问题；排序阶段构造三类特征，即商品特征（品类、甜度、酸度、脆度、产地、规格、单价、糖度、应季月份、品级与认证）、用户特征（由口味偏好问卷获得的显式偏好，以及由浏览、搜索、收藏、加购、下单、评价等行为加权聚合并进行时间衰减得到的隐式偏好）与时空情境特征（当前季节、节日、时段、配送区域），采用基于内容的匹配与多因素加权模型计算候选商品得分，并对重复购买周期、忌口冲突与负反馈施加惩罚项。针对水果强时令、强复购、易腐坏的领域特性，模型引入时间衰减函数刻画偏好漂移，引入多样性打散策略提高品类覆盖，并将库存压力纳入排序权重以实现推荐与库存协同、减少滞销损耗。系统输出可读的推荐依据（如"当季上市""口味匹配""同类复购""近七日热销"），并允许商家调整权重方案、允许用户反馈修正。实验采用自建模拟数据集与公开生鲜购物篮数据集，以准确率、NDCG、商品覆盖率与长尾商品曝光占比作为评价指标，与随机推荐、热销榜单、纯内容匹配及协同过滤基线进行对比，并针对新用户冷启动、候选商品不足、忌口冲突、库存为零与推荐计算异常等边界条件进行验证。

### 1. 技术要求（模板要求 ≥150 字，本稿约 330 字）

**【填写内容】**

系统采用前后端分离的 B/S 架构。后端基于 Java 17 与 Spring Boot 3.5 自行搭建分层工程骨架，按照 Controller、Service、Mapper 三层组织代码。身份认证采用 JSON Web Token 实现无状态登录，授权基于 RBAC 模型控制用户、角色与菜单权限，通过拦截器与自定义权限注解完成接口级鉴权，用户密码使用 BCrypt 算法加密存储。持久层采用 MyBatis-Plus 操作 MySQL 8 数据库，通过事务与条件更新语句（判断影响行数）保证并发下单场景下的库存扣减一致性。缓存使用 Redis，用于热点商品数据与推荐结果缓存。前端消费者端采用 Vue 3 与 Vant 组件库构建移动端 H5 页面，商家后台采用 Vue 3 与 Element Plus 构建，统计图表使用 ECharts 绘制。多因素加权推荐模块使用 Java 实现，包含特征构建、多通道召回与加权排序，并配套离线评估脚本完成算法效果验证。接口文档使用 Knife4j 自动生成，接口遵循统一的响应体结构与错误码规范。开发过程使用 Git 进行版本管理，使用 JUnit 5、Apifox 与 JMeter 完成单元测试、接口测试与并发测试，重点验证库存扣减、订单状态流转、模拟支付幂等与售后状态一致性。

### 2. 工作要求（模板要求 ≥100 字，本稿约 240 字）
