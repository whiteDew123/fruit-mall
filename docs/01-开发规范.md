# 开发规范与项目结构

> 面向人类开发者的完整版；面向 AI Agent 的精简强制版在根目录 `AGENTS.md`，两者冲突时以 `AGENTS.md` 为准并回头修正本文档。
> 版本：v0.3（2026-09-24）。骨架搭建完成后，需要把实际落地的类名与本文档核对一遍。

---

## 1. 三条组织原则

1. **自建精简骨架，不引入第三方后台框架。** 认证、权限、日志、分页、异常这些基础设施自己写，代码量约 1500-2500 行，大半是模板化代码。好处是全部代码可解释、可修改，答辩时"哪些是我写的"这个问题不存在。
2. **按业务分包，不按层分包。** 一个功能的 Controller、Service、Mapper、实体放在同一个业务包内，改动一个功能只在一个目录里动。
3. **能用机器拦住的，不靠自觉。** 格式交给 ESLint/Prettier，编译必须通过，状态变更只有一个入口。规范文档只写机器管不住的部分。

## 3. 后端结构

### 3.1 为什么是单 Maven 工程

自建骨架下没有"基座模块"需要隔离，拆多模块只会带来依赖顺序、循环依赖、打包配置三类成本。用**包边界**达到同样的隔离效果，等真要拆时把包整体搬走即可。

### 3.2 包结构

```
fruit-mall/server/src/main/java/com/fruitmall/
├── FruitMallApplication.java
├── common/                       # 基础设施（第 12 节有完整清单）
│   ├── result/                   # Result、PageResult、ResultCode
│   ├── exception/                # BizException、GlobalExceptionHandler
│   ├── annotation/               # @RequiresPermission、@OperLog
│   ├── aspect/                   # OperLogAspect（操作日志切面）
│   ├── interceptor/              # AuthInterceptor（登录态与权限校验）
│   ├── config/                   # WebMvcConfig、MybatisPlusConfig、Knife4jConfig、RedisConfig
│   ├── util/                     # JwtUtil、PasswordUtil
│   ├── enums/                    # ★所有状态枚举的唯一来源
│   ├── constant/                 # 常量与错误码
│   └── domain/                   # BaseEntity（业务表公共字段基类）
├── auth/                         # 登录注册、token 签发与校验、当前登录用户上下文
├── system/                       # 系统管理：后台用户、角色、菜单权限（sys_ 前缀表）
├── product/                      # 商品、分类、特色属性
├── inventory/                    # 库存批次与流水
├── cart/
├── order/                        # 订单 + 订单状态机
├── payment/                      # 模拟支付 + 支付状态机
├── fulfillment/                  # 履约 + 履约状态机
├── aftersale/                    # 售后 + 售后状态机
├── review/
├── behavior/                     # 行为埋点（推荐数据源）
├── recommend/                    # 推荐：feature / recall / rank / reason / eval / config
└── stat/                         # 经营分析
```

每个业务包内部结构一致：

```
product/
├── controller/       # 消费者端与共用接口
├── admin/            # 商家后台接口（Controller 层）
├── service/ + service/impl/
├── mapper/           # MyBatis-Plus Mapper
├── domain/           # 数据库实体（与表一一对应）
├── dto/              # 入参对象（带校验注解）
├── vo/               # 出参对象（面向前端）
└── query/            # 查询条件对象
```

### 3.3 分层职责与边界

| 层 | 允许做的事 | 禁止做的事 |
|---|---|---|
| Controller | 参数接收与 `@Valid` 校验、权限注解、调用 Service、返回 `Result` | 写业务逻辑、直接调 Mapper、改状态 |
| Service | 业务规则、状态机调用、事务边界、组装 VO | 直接处理 HTTP 对象、绕过状态机改状态 |
| Mapper | 单表或明确的多表查询、条件更新 | 承载业务判断、被 Controller 直接调用 |
| domain | 与表字段一一对应 | 掺杂展示字段、放业务方法 |
| dto / vo | 入参校验 / 出参裁剪 | 直接暴露敏感字段（手机号、地址需脱敏） |

一条硬规矩：**状态变更只能由 Service 调用状态机完成**，Mapper 里不出现裸的 `update xxx set status = ...`。

## 6. 接口规范

### 6.1 统一响应体

```json
{ "code": 200, "message": "操作成功", "data": { } }
```

`code` 与 HTTP 状态码保持一致；业务细分原因写在 `message` 里，前端可直接展示。

| 状态码 | 含义 | 典型场景 |
|---|---|---|
| 200 | 成功 | — |
| 400 | 参数校验失败 | DTO 校验不通过、金额与订单不符 |
| 401 | 未登录或 token 失效 | token 缺失、过期 |
| 403 | 无权限 | 越权访问他人订单、角色权限不足 |
| 404 | 资源不存在 | 商品、订单编号不存在 |
| 409 | 状态冲突 | 非法状态流转、商品已下架、库存不足 |
| 500 | 系统异常 | 未预期异常，日志记录堆栈 |

### 6.2 分页

请求：`pageNum`（从 1 开始）、`pageSize`（默认 10，上限 100）。
响应：`data` 为分页对象。

```json
{ "code": 200, "message": "操作成功",
  "data": { "pageNum": 1, "pageSize": 10, "total": 57, "list": [ ] } }
```

### 6.3 其它约定

- **HTTP 方法**：查询 `GET`，新增 `POST`，整体更新 `PUT`，删除 `DELETE`，状态变更用明确动作路径（如 `POST /api/shop/order/{orderNo}/cancel`）。
- **鉴权**：除登录注册、商品浏览、推荐等公开接口外，其余接口须带 `Authorization: Bearer <token>`；消费者接口在 Service 层额外校验数据归属。
- **权限**：后台接口在方法上标注 `@RequiresPermission("product:create")`，由拦截器统一校验。
- **操作日志**：后台写操作标注 `@OperLog(module = "商品管理", action = "新增商品")`，切面自动落库。
- **幂等**：下单、支付回调、退款确认必须幂等，用业务唯一键（订单号、支付流水号）加唯一索引兜底。
- **参数校验**：入参在 DTO 层用 `@NotNull` / `@Min` / `@Size` 标注；业务规则（库存、状态、归属、金额）在 Service 层二次校验。
- **接口文档**：用 Knife4j 自动生成，**不手写接口文档**，方法上补 `@Operation` 说明即可。
- **时间与金额**：时间统一 `yyyy-MM-dd HH:mm:ss`；金额 Java 用 `BigDecimal`、MySQL 用 `DECIMAL(10,2)`，禁止 double。

## 7. 数据库规范

- **命名**：表名与字段名小写下划线；不使用拼音缩写。
- **必备字段**：每张业务表包含 `id`（bigint 自增主键）、`create_time`、`update_time`、`create_by`、`update_by`、`deleted`（0 未删 / 1 已删，MyBatis-Plus 逻辑删除）。审计字段由 `MetaObjectHandler` 自动填充，业务代码不手工赋值。
- **状态字段**：统一命名为 `status`，取值只定义在 `docs/05-数据库设计.md` 与 `com.fruitmall.common.enums` 两处，且必须一致。
- **索引**：外键字段建普通索引；查询热点建联合索引（如 `fm_user_behavior(member_id, create_time)`）；订单号、支付流水号、批次号建唯一索引。
- **外键**：不使用数据库外键约束，一致性由 Service 层与校验脚本保证（便于造数据与迁移）。
- **库存扣减**：`stock` 为可售库存，扣减必须用条件更新
  `UPDATE fm_product_sku SET stock = stock - #{qty} WHERE id = #{id} AND stock >= #{qty}`
  并判断影响行数；**禁止"先查再减"**。
- **SQL 管理**：建表与初始化脚本放 `fruit-mall/deploy/sql/`，按编号命名（`01_schema.sql`、`02_init_data.sql`、`03_mock_data.sql`）；**禁止手工改库不入脚本**。
- **不使用自动建表**：JPA/Hibernate 的 `ddl-auto` 一律不用；MyBatis-Plus 也不接管 DDL。

## 8. 状态机与事务规范

### 8.1 状态机

订单、支付、履约、售后四个状态机，每个一个类，统一对外暴露 `transition(业务号, 目标动作)`，内部校验"当前状态是否允许该动作"，不允许则抛 `BizException`（HTTP 409）并记录日志。状态字段只能被状态机修改。

### 8.2 事务边界（最容易出错的地方）

| 操作 | 事务内 | 事务外 |
|---|---|---|
| 提交订单 | 库存条件扣减、订单头写入、订单项写入、库存流水写入 | 行为埋点、通知 |
| 支付成功 | 订单状态迁移、支付单状态迁移、库存实扣、库存流水 | 推荐缓存刷新、埋点 |
| 取消订单 | 订单状态迁移、库存回补、库存流水 | 通知 |
| 售后审核通过 | 售后单状态迁移、退款记录写入、（退货场景）库存暂存回补 | 通知 |

原则：**事务内只做数据一致性必需的事**；耗时的、可失败的、与外部交互的动作放事务外，避免长事务。

## 9. 前端开发规范

- 请求统一走 `utils/request.js`：自动带 token、统一处理 401 跳登录、统一错误提示；页面里不直接写 axios。
- 页面级组件以 `index.vue` 结尾；可复用组件放 `components/`。
- 样式用 CSS 变量定义主色、间距、圆角，不散落魔法数字。
- 所有列表页必须有加载态、空状态、错误态三种表现。
- **埋点**：浏览商品详情、搜索、加购、下单、评价、点"不感兴趣"时调用埋点接口。这是推荐系统的数据源，功能写完就顺手埋，不要积压。
- 格式化交给 ESLint + Prettier，不靠人工注意。

## 10. Git 规范

- 每天至少提交一次，收工前提交。
- 提交信息格式：`类型(模块): 说明`，类型取 `feat / fix / refactor / docs / test / chore`。示例：`feat(order): 完成订单提交与库存条件扣减`。
- 一次提交只做一件事；不混合"新功能"与"格式调整"。
- 不提交 `target/`、`node_modules/`、本地配置、任何密码与密钥。
- 每完成一个模块打一个 tag（如 `v0.1-product`），便于回溯与演示回滚。

## 12. 骨架自建清单（第 1-2 天的任务单）

自建骨架要落地的东西，按实现顺序：

| 序号 | 组件 | 说明 |
|---|---|---|
| 1 | 工程初始化 | Spring Boot 3 + JDK 17 + Maven，`application.yml` 多环境配置 |
| 2 | 统一响应 | `Result`、`PageResult`、`ResultCode` 枚举 |
| 3 | 全局异常 | `BizException` + `@RestControllerAdvice`，分类处理参数/认证/权限/业务/系统异常 |
| 4 | 持久层 | MyBatis-Plus 配置、分页插件、`MetaObjectHandler` 自动填充审计字段、逻辑删除 |
| 5 | 认证 | 登录、BCrypt 密码校验、`JwtUtil` 签发与解析、token 过期处理 |
| 6 | 权限 | `sys_user`/`sys_role`/`sys_menu`/`sys_user_role`/`sys_role_menu` 五张表；`@RequiresPermission` 注解 + `AuthInterceptor` 校验 |
| 7 | 登录上下文 | `UserContext`（ThreadLocal）提供当前用户与角色 |
| 8 | 操作日志 | `@OperLog` 注解 + AOP 切面 + `sys_oper_log` 表，异步落库 |
| 9 | 接口文档 | Knife4j（OpenAPI 3）配置与分组 |
| 10 | 前端脚手架 | `web-shop`（Vant）与 `web-admin`（Element Plus）两个 Vite 工程、axios 封装、路由与登录页 |

依赖清单控制在：`spring-boot-starter-web`、`mybatis-plus-spring-boot3-starter`、`mysql-connector-j`、`spring-boot-starter-data-redis`、`spring-boot-starter-validation`、`spring-boot-starter-aop`、`jjwt`、`lombok`、`knife4j-openapi3-jakarta-spring-boot-starter`。

## 13. 参考项目与对标

这些项目**只作为阅读参考，不引入代码**：

| 项目 | 参考什么 |
