# 接口约定

> 本文档只写**接口清单、错误码与跨接口的通用约定**；具体参数与响应结构由 Knife4j 自动生成，
> 不手写、不重复维护（启动后端后访问 `http://localhost:8080/doc.html`）。
> 版本：v0.1（2026-09-28）。

---

## 1. 通用约定

| 项 | 约定 |
|---|---|
| 消费者端前缀 | `/api/shop/{模块}/{资源}` |
| 商家后台前缀 | `/api/admin/{模块}/{资源}` |
| 登录注册 | `/api/auth/**` |
| 统一响应 | `{ code, message, data }`，`code` 与 HTTP 状态码一致 |
| 分页请求 | `pageNum`（从 1 开始）、`pageSize`（默认 10、上限 100） |
| 分页响应 | `data` 为 `{ pageNum, pageSize, total, list }` |
| 时间格式 | `yyyy-MM-dd HH:mm:ss`（由 `JacksonConfig` 统一处理 Java 8 时间类型） |
| 金额 | `BigDecimal` / `DECIMAL(10,2)`，禁止 double、float |
| 鉴权 | 请求头 `Authorization: Bearer <token>`；白名单接口除外 |
| 权限 | 后台接口方法上标注 `@RequiresPermission("{模块}:{操作}")` |
| 操作日志 | 后台**写操作**必须标注 `@OperLog(module = "...", action = "...")` |
| 幂等 | 下单、支付回调、退款确认必须幂等，业务唯一键加唯一索引兜底 |
| 文档 | Knife4j 自动生成，方法上补 `@Operation` 说明即可 |

### 1.1 免登录白名单

白名单集中在 `application.yml` 的 `fruit-mall.auth.exclude-paths` 维护，逗号分隔，**只改配置不改代码**。
当前内容：

```
/api/auth/admin/login,/api/auth/member/login,/api/auth/member/register
```

后续商品浏览、分类检索、首页推荐等公开接口在此追加。

## 2. 错误码

`code` 与 HTTP 状态码一致，业务细分原因写在 `message` 中，前端可直接展示。

| code | 含义 | 典型场景 |
|---|---|---|
| 200 | 成功 | — |
| 400 | 参数校验失败 | DTO 校验不通过、登录名或密码错误、请求体格式错误 |
| 401 | 未登录或令牌失效 | 未携带令牌、令牌过期、令牌被篡改 |
| 403 | 无权限 | 角色缺少权限标识、账号被禁用、越权访问他人数据 |
| 404 | 资源不存在 | 接口路径不存在、商品或订单编号不存在 |
| 409 | 状态冲突 | 非法状态流转、库存不足、商品已下架 |
| 500 | 系统异常 | 未预期异常，堆栈只进日志不返回前端 |

## 3. 已实现接口清单

| 模块 | 方法 | 路径 | 权限标识 | 说明 |
|---|---|---|---|---|
| 登录注册 | POST | `/api/auth/admin/login` | 公开 | 后台用户登录，返回 JWT 与权限集合 |
| 登录注册 | GET | `/api/auth/profile` | 需登录 | 获取当前登录用户信息，用于前端恢复登录态 |
| 系统管理-用户 | GET | `/api/admin/system/user/list` | `system:user:list` | 分页查询后台账号，手机号脱敏 |
| 系统管理-用户 | POST | `/api/admin/system/user` | `system:user:create` | 新增后台账号并关联角色，写操作记录操作日志 |

### 3.1 操作日志的落库范围

`@OperLog` 切面只记录**业务方法真正执行**的后台写操作。以下情况不产生操作日志：

- 未登录（401）与权限不足（403）：请求在 `AuthInterceptor` 阶段就被拦下，业务方法未执行；
- 参数校验失败（400）：请求在进入方法前被 Spring Validation 拦下。

因此操作日志反映的是"实际执行的写操作"，包含成功与**执行中失败**两种结果（`result_status` 10 / 20），
失败时 `error_msg` 记录异常原因。若后续需要把 401/403 也纳入安全审计，可在全局异常处理中补充记录。

## 4. 待补充

随模块开发逐项补齐清单，参数细节以 Knife4j 为准：

| 模块 | 计划接口 | 计划权限标识 |
|---|---|---|
| 分类管理 | 增删改查、排序 | `category:list` / `category:create` / `category:update` / `category:delete` |
| 商品管理 | 建档、编辑、上下架、特色属性、图片 | `product:list` / `product:create` / `product:update` / `product:status` / `product:attr:update` |
| 库存管理 | 批次入库、库存调整、报损、流水 | `inventory:inbound` / `inventory:adjust` / `inventory:loss` / `inventory:txn:list` |
| 订单管理 | 列表、详情、取消、备注 | `order:list` / `order:detail` / `order:cancel` / `order:remark` |
| 履约管理 | 列表、分拣、配送、签收、异常 | `fulfillment:pick` / `fulfillment:deliver` / `fulfillment:sign` / `fulfillment:exception` |
| 售后管理 | 审核、退货收货、退款确认 | `aftersale:audit` / `aftersale:receive` / `aftersale:refund` |
| 评价管理 | 列表、回复、隐藏 | `review:list` / `review:reply` / `review:status` |
| 会员管理 | 列表、详情 | `member:list` / `member:detail` |
| 经营分析 | 销售趋势、品类占比、商品销量 TOP | `stat:sales` / `stat:category` / `stat:product` |
| 推荐运营 | 权重方案、发布、置顶屏蔽保量、效果 | `recommend:config:list` / `recommend:config:publish` / `recommend:rule:update` / `recommend:effect` |

权限标识与 `sys_menu.perm` 一一对应，新增权限标识时必须同时更新 `deploy/sql/02_init_data.sql` 与本节清单。
