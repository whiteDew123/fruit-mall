## 2. 后端技术说明

### 2.1 Java 17

选择 LTS 版本，兼顾新语法（`record`、文本块、`switch` 表达式）与生态稳定性。本机路径 `E:\developmentTools\java17`，已配置为用户级 `JAVA_HOME`。

注意：机器 PATH 上还有一个 Oracle Java 8 的 shim，命令行的 `java` 命令可能仍指向 8；Maven 与 IDEA 走 `JAVA_HOME`，不受影响。

### 2.2 Spring Boot 3.5

应用的骨架与依赖管理。选 3.x 而非 4.x 的原因是 3.x 生态资料充足、第三方库适配成熟，避免为版本号付出排查成本。使用 3.x 需要 JDK 17 起，且命名空间为 Jakarta（`jakarta.*`），这会影响所有 Servlet/Validation 相关注解的 import。

本项目用到的 Boot Starter：

| Starter | 用途 |
|---|---|
| `spring-boot-starter-web` | REST 接口、内嵌 Tomcat、Jackson |
| `spring-boot-starter-validation` | `@NotNull` 等参数校验 |
| `spring-boot-starter-aop` | 操作日志切面、权限校验切面 |
| `spring-boot-starter-data-redis` | Redis 客户端（Lettuce） |
| `spring-boot-starter-test` | 单元测试与 MockMvc |

### 2.3 MyBatis-Plus

持久层框架，替代手写大量 XML。本项目的具体用法：

- **分页插件**：分页查询统一走插件，接口入参 `pageNum`/`pageSize`，避免手写 limit。
- **条件更新**：库存扣减使用 `UpdateWrapper` 生成 `UPDATE ... SET stock = stock - n WHERE id = ? AND stock >= n`，通过影响行数判断是否成功。这是防止超卖的核心手段。
- **逻辑删除**：`deleted` 字段由 `@TableLogic` 接管，业务代码不写 `where deleted = 0`。
- **审计字段自动填充**：实现 `MetaObjectHandler`，自动写入 `create_time`、`update_time`、`create_by`、`update_by`。
- **不使用**：不接管建表（不用 `ddl-auto`），表结构由 `deploy/sql/` 脚本维护。

### 2.4 Spring AOP 与自定义注解

两个切面：

| 注解 | 切面 | 作用 |
|---|---|---|
| `@OperLog` | `OperLogAspect` | 拦截后台写操作，记录操作人、模块、动作、参数、结果、耗时、IP，异步写入 `sys_oper_log` |
| `@RequiresPermission` | 由拦截器配合 | 校验当前用户是否具备指定权限标识，权限不足返回 403 |

### 2.5 全局异常处理

`@RestControllerAdvice` 统一捕获四类异常：参数校验异常（400）、认证异常（401）、权限异常（403）、业务异常 `BizException`（409/400）、以及兜底系统异常（500）。返回体统一为 `{ code, message, data }`，堆栈只进日志不返回前端。

### 2.6 事务

事务边界只包含数据一致性必需的操作（见 `docs/01-开发规范.md` 第 8 节）。耗时操作、外部调用、埋点一律放在事务外，避免长事务。

## 3. 前端技术说明

两个独立工程，互不引用，共用一套请求封装思路。

### 3.1 消费者端 `web-shop`

| 技术 | 用途 |
|---|---|
| Vue 3（组合式 API） | 页面与组件 |
| Vite | 开发服务器、热更新、打包 |
| Vant 4 | 商品卡片、列表、表单、弹层等移动端组件 |
| Vue Router 4 | 页面路由 |
| Pinia | 登录态、购物车角标等全局状态 |
| Axios | 统一请求封装（带 token、统一错误提示） |

移动优先的响应式布局，演示时手机浏览器与桌面浏览器都能直接打开。

### 3.2 商家后台 `web-admin`

| 技术 | 用途 |
|---|---|
| Vue 3 + Vite | 同上 |
| Element Plus | 表格、表单、分页、弹窗等后台组件 |
| ECharts | 经营分析图表（销售趋势、品类占比、滞销商品、推荐效果） |
| Vue Router / Pinia / Axios | 同上 |

后台布局自建（侧边栏 + 顶栏 + 内容区），不引入重型 admin 模板，避免为模板的抽象层付出学习成本。

### 3.3 前端约定

- 请求统一走 `utils/request.js`，页面内不直接写 axios。
- 列表页必须有加载态、空状态、错误态。
- 埋点：浏览详情、搜索、加购、下单、评价、"不感兴趣"六类行为调用埋点接口，作为推荐系统的数据源。
- 格式化交给 ESLint + Prettier。

## 4. 数据存储与缓存

### 4.1 MySQL 8

存储全部业务数据：商品与特色属性、SKU、批次库存与库存流水、购物车、订单与订单项、支付记录、履约记录、售后单、评价、用户行为埋点、推荐配置与推荐留痕。

关键设计：

- SPU/SKU 两级商品结构，价格与库存挂在 SKU 上。
- 库存按批次管理（入库日期、保质期、剩余量），支撑临期预警与先进先出扣减。
- 金额一律 `DECIMAL(10,2)`；不使用数据库外键，一致性由 Service 与校验脚本保证。
- 建表与初始化脚本放 `fruit-mall/deploy/sql/`，禁止手工改库不入脚本。

### 4.2 Redis

用途限定为两类，**登录态不落 Redis**（JWT 无状态）：

1. 热点商品与分类树缓存；
2. 推荐结果缓存（key 带权重方案版本号，配置变更即失效）。

本机为 3.2.100（2016 年的 Windows 移植版），基础命令可用；若后续需要更复杂的数据结构或连接报错，再升级版本。Redis 不可用时应降级为直接查库，不能让商品列表打不开。

## 5. 推荐算法的实现技术

**全部用 Java 实现，不引入 Python 服务、不引入机器学习库。** 理由：算法本质是向量运算与加权求和，与语言无关；同工程实现可省去跨语言部署与接口设计；数据量（500 用户 × 200 个商品 × 数万条行为）在内存中计算为毫秒级，不需要 Spark、Elasticsearch 或向量数据库。

用到的技术手段：

| 环节 | 实现要点 |
|---|---|
| 特征构建 | 商品特色属性归一化为定长向量；用户画像由行为日志按"行为权重 × 时间衰减"加权聚合 |
| 召回 | 内容相似（余弦相似度）、时令匹配、热销榜单、物品协同过滤（共现矩阵）、库存协同，五通道合并去重 |
| 排序 | 多因素加权求和，特征缺失时该维度不参与分母、其余权重自动重新归一化 |
| 打散 | 贪心 MMR，保证 Top-N 覆盖多个品类 |
| 可解释 | 记录各因素原始分、权重、贡献值，生成中文推荐理由，写入 `fm_recommend_trace` |
| 评估 | 带 `main` 方法的评估类，按时间切分数据，计算 Precision@K、NDCG、覆盖率、长尾曝光占比，输出 CSV 用 Excel 出图 |

详细设计见 `docs/04-推荐算法实现方案.md`。

## 6. 安全与权限

| 项 | 方案 |
|---|---|
| 密码存储 | BCrypt 加密（`spring-security-crypto`），不存明文、不用 MD5 |
| 登录态 | JWT 无状态，请求头 `Authorization: Bearer <token>` |
| 权限模型 | RBAC：用户—角色—菜单（权限标识）三张主表加两张关联表 |
| 接口鉴权 | 拦截器统一校验 token；`@RequiresPermission("product:create")` 校验功能权限 |
| 数据归属 | Service 层校验（会员只能访问自己的购物车、订单、地址），不依赖前端隐藏按钮 |
| 数据脱敏 | 手机号、收货地址在列表页脱敏；只有下单与履约环节展示完整信息 |
| 隐私原则 | 演示数据为模拟或脱敏数据，不采集与业务无关的个人信息 |
| 敏感信息 | 数据库密码、JWT 密钥走本地配置，不提交进仓库 |

## 10. 为什么不用其它方案（答辩备用）

| 候选 | 不采用的原因 |
|---|---|
| 若依（RuoYi）等后台框架 | `RuoYi-Vue-Plus` 有 30 来个 Maven 模块，对单商家商城属于过度工程；若依官方仓库没有 Spring Boot 3 版本（v3.9.1 是 Boot 2.5 + JDK 8，v3.9.2 直接跳到 Boot 4），为满足版本要求要连带换认证框架、换持久层、升级 Redis，代价与收益不成比例 |
| Python 推荐服务 | 本课题算法是向量运算与加权求和，Java 完全胜任；额外进程带来跨语言部署与接口设计成本，且数据量在内存可算 |
| 深度学习推荐 | 数据规模支撑不了，且难以在答辩中讲清；用规则 + 统计 + 协同过滤更适合本课题 |
| 微信小程序 | 需要账号资质、域名 HTTPS 备案、主包 2MB 限制，且答辩现场依赖微信登录与体验成员配置，演示风险高于 H5 |
| Elasticsearch / MongoDB / 消息队列 | 本课题的数据量与检索需求用 MySQL 全文检索与分类筛选即可满足，引入后部署与排查成本显著上升 |

## 11. 版本锁定与变更规则

- 后端版本以 `fruit-mall/server/pom.xml` 为准，前端以各 `package.json` 与 `package-lock.json` 为准。
- 骨架搭建完成后，把实际解析到的版本号回填到本文档第 1 节表格。**已于 2026-09-28 完成首次回填**：Spring Boot 3.5.16、MyBatis-Plus 3.5.8、Knife4j 4.5.0、JJWT 0.13.0、mysql-connector-j 9.7.0，后端运行时依赖共 82 个。
- 升级 Spring Boot 主版本、替换认证或持久层框架属于重大变更，需先确认并同步更新 `AGENTS.md`、`docs/01-开发规范.md` 与本文档。
